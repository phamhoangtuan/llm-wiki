Good Code, Bad Code

By Tom Longbook2021-01-01Ingested: 2026-06-08
clean-codeengineeringdesign-principlesmaintainability

Summary

A 338-page guide to thinking like a software engineer, not just a coder. Distinguishes professional engineering (code that lives for years, withstands team modifications, carries real-world consequences) from casual coding. Introduces the 4 goals of quality code and the 6 tactical pillars: Readable, No Surprises, Hard to Misuse, Modular, Reusable, and Testable.

Core Message

High-quality code isn't an aesthetic preference — it's a practical necessity for business stability and user safety. Writing code that machines execute is easy. Writing code that humans maintain, extend, and trust for years is an art.

Key Takeaways

  1. Engineering ≠ Coding: Engineering code survives years of changes, multiple developers, and has real-world consequences
  2. 4 Goals: Code must work, keep working, be adaptable to change, and leverage existing solutions
  3. 6 Pillars: Readable, No Surprises (functions do exactly what they promise), Hard to Misuse (design prevents errors), Modular (Lego, not glued wood), Reusable/Generalizable, Testable
  4. Abstraction layers: Clean APIs with hidden implementation details; small functions, cohesive classes, interfaces at boundaries
  5. Less Haste, More Speed: Upfront investment in quality prevents future disasters — true speed comes from sustainability
