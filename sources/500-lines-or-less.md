## Summary

*500 Lines or Less* is the fourth volume in the **Architecture of Open Source Applications (AOSA)** series, edited by Michael DiBernardo. Unlike earlier volumes focused on large-scale systems, this book studies design decisions "in the small" — the fundamental choices made when building from scratch.

## Key Themes

### The 500-Line Constraint

Every program is written in **fewer than 500 lines** of source code. Authors are forbidden from using "cheap tricks" (space-saving hacks) — code must remain useful and pedagogically sound. The constraint forces focus on core abstractions.

### Active Learning Methodology

Readers are encouraged to:

1. **Predict the solution** before reading — how would you decompose the problem?
2. **Identify surprises** after reading — what did the professional do differently?

### Code as Literature

Contributors like Brandon Rhodes argue correct code is a form of thought — one of the most transparent. The editors treat **code formatting as graphic design** to maximize clarity. By stripping away "mundane equipment" of production software, the book reveals structural principles of robust architecture.
