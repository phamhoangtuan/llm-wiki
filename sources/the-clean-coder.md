# The Clean Coder: Code of Conduct for Professionals

**Author:** Robert C. Martin | **Type:** Ebook

## Summary

While *Clean Code* focuses on the code artifact, *The Clean Coder* addresses the conduct of the individual professional. Professionalism is defined as a badge of honor tied to responsibility and accountability — a professional takes personal responsibility for the function and structure of their work.

## Core Behavioral Disciplines

### Saying No

Professionals must say "no" to unrealistic deadlines and poor requirements. This involves an adversarial but productive relationship with management: managers defend schedules, programmers defend feasibility — the tension produces the best outcome.

### Saying Yes

Commitment uses a precise language: "I will... by..." (three stages: say, mean, do). If a commitment cannot be met, the professional raises a red flag as early as possible.

### Preparedness and the Zone

Professionals know when they are unfit to code (tired, distracted). Notably, the book advises *against* "the Zone" or "Flow," characterizing it as a diminished rational state where tunnel vision replaces big-picture awareness.

## Testing and QA

- **Zero Defects Goal**: Developers release code expecting QA to find nothing. Post-release bugs trigger process investigation.
- **Test Automation Pyramid**: Unit (~100% coverage) → Component → Integration → System → Manual Exploratory
- **TDD as Professional Option**: TDD provides certainty, courage, and documentation for long-term system health

## Mentoring and Craftsmanship

Craftsmanship is a "meme" handed from person to person. University programs fail to prepare graduates for industry realities, so senior programmers have a professional duty to mentor juniors.

## Tooling

Professional toolkit: distributed source control (git), language-specific IDEs, continuous build engines (Jenkins). "The code is the design" — the professional manages detail so clearly that intent is never obscured.
